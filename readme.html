Hari's Multicuisine Restaurant - Microservices System on Kubernetes

Production-ready, highly available, distributed cloud-native restaurant management application designed to handle live catalog browsing, Indian GST billing (5%), asynchronous event streaming with Apache Kafka, real-time consumer terminal logging, and persistent relational data storage on Kubernetes.

Architecture Core: Python Flask (Backend) • Nginx (Frontend) • MySQL (StatefulSet Persistence) • Apache Kafka & Zookeeper (Event Backbone) • Python Consumer Worker (Real-time DB sync & CLI logger).

1. Project High-Level Architecture Overview

System contains an Nginx static frontend UI, Python Flask API gateway backend, MySQL StatefulSet cluster, Apache Kafka & Zookeeper event backbone, and a Python consumer worker pod.

2. Folder By Folder Deep-Dive & Architectural Explanations

Folder 1: /backend

Flask web application container gateway. Acts as the core transactional engine bridging MySQL database and Kafka broker.

+------------------------------------------------------------------------+
|                            BACKEND FOLDER                              |
|                                                                        |
|   requirements.txt  --------->  Dockerfile  --------->  app.py         |
|   (Flask, MySQL,                (Python 3.10            (Endpoints &   |
|    Kafka dependencies)           Slim Container)         Event Stream) |
+------------------------------------------------------------------------+
  • backend/app.py: Initializes Flask server and configures CORS. Connects to MySQL pod using mysql-headless. Exposes /api/menu, /api/analytics/daily-summary, and /api/orders/pay (computes 2.5% CGST + 2.5% SGST, writes records, and emits message to Kafka topic order-payments).
  • backend/Dockerfile: Uses python:3.10-slim official base image, installs dependencies, and exposes listening port 5000.
  • backend/requirements.txt: Production dependencies: Flask==3.0.0, flask-cors==4.0.0, mysql-connector-python==8.2.0, kafka-python==2.0.2.

Folder 2: /consumer

Asynchronous background daemon event processor pod. Continuously polls and streams real-time payment transactions from Apache Kafka.

+------------------------------------------------------------------------+
|                            CONSUMER FOLDER                             |
|                                                                        |
|   requirements.txt  --------->  Dockerfile  --------->  consumer.py    |
|   (kafka-python,                (Python Worker          (Listener &    |
|    dbutils, pymysql)             Container)              DB Committer) |
+------------------------------------------------------------------------+
  • consumer/consumer.py: Implements PooledDB (PyMySQL) for resilient connection management. Subscribes to order-payments topic, marks orders as PAID, stores records in payments audit table, commits partition offset, and prints formatted receipts to stdout.
  • consumer/Dockerfile: Builds lightweight container running python consumer.py.
  • consumer/requirements.txt: Dependencies: kafka-python==2.0.2, dbutils==3.1.0, pymysql==1.1.0.

Folder 3: /database

Relational database initialization script and seed dataset.

+------------------------------------------------------------------------+
|                            DATABASE FOLDER                             |
|                                                                        |
|                             schema.sql                                 |
|         +-----------------------+------------------------+             |
|         |                       |                        |             |
|         v                       v                        v             |
|    menu_items                 orders                  payments         |
|  (Catalog items)        (Table order master)    (GST & transaction)    |
+------------------------------------------------------------------------+
  • database/schema.sql: Configures restaurant_db with tables: menu_items, orders, order_items, and payments (storing subtotal, 2.5% CGST, 2.5% SGST, grand total, and payment method).

Folder 4: /frontend

Nginx-served responsive client user interface.

+------------------------------------------------------------------------+
|                            FRONTEND FOLDER                             |
|                                                                        |
|    index.html  <====>  style.css  <====>  app.js  <====>  assets/      |
|    (UI Structure)      (Styling)          (Logic/Tax)     (Images)     |
|                                                                        |
|                     Dockerfile (Nginx Base Image)                      |
+------------------------------------------------------------------------+
  • frontend/index.html: Modern dashboard layout with digital clock, business metrics badges, category tabs, food grid, floating tray, and GST tax invoice modal.
  • frontend/app.js: Handles clock ticking, analytics loading, dynamic dish cards with interactive quantity counters, GST math (2.5% CGST + 2.5% SGST), and payment API calls.
  • frontend/style.css: Indian restaurant theme styling, grid layout, floating tray, and modal styling.
  • frontend/Dockerfile: Hosts static web assets under /usr/share/nginx/html via nginx:alpine.

Folder 5: /k8s (Kubernetes Manifests)

Kubernetes Infrastructure as Code (IaC) configuration manifests.

  • k8s/database/: secret.yml (credentials), headless-service.yml (internal DNS), statefulset.yml (persistent storage MySQL pod).
  • k8s/kafka/: zookeeper.yml (cluster coordination), kafka-service.yml (service DNS), kafka-statefulset.yml (Kafka message broker).
  • k8s/backend/: backend-deployment.yml (2 replicas Flask API), backend-service.yml (ClusterIP load balancer).
  • k8s/consumer/: payment-consumer-deployment.yml (Python worker daemon).
  • k8s/frontend/: frontend-configmap.yml (Nginx reverse proxy), frontend-deployment.yml (2 replicas UI), frontend-service-nodeport.yml (external access port 30080).

Folder 6: /postman

Automated regression tests, JSON schema validation, and environment variables.

  • postman/restaurant-collection.json: 4 API requests with assertions for status code, schema, and 5% GST calculations.
  • postman/restaurant-environment.json: Environment profiles maintaining base_url, table_number, and dynamic test_order_id.

3. Step-by-Step Execution Commands

Step 1: Initialize Minikube Cluster

# Start local single-node Kubernetes cluster
minikube start --driver=docker

# Verify node connectivity
kubectl get nodes

Step 2: Deploy Database & Message Streaming Infrastructure

# Deploy MySQL StatefulSet and headless networking
kubectl apply -f k8s/database/secret.yml
kubectl apply -f k8s/database/headless-service.yml
kubectl apply -f k8s/database/statefulset.yml

# Deploy Zookeeper and Kafka broker
kubectl apply -f k8s/kafka/zookeeper.yml
kubectl apply -f k8s/kafka/kafka-service.yml
kubectl apply -f k8s/kafka/kafka-statefulset.yml

# Watch infrastructure pods until status reaches 1/1 Running
kubectl get pods -w

Step 3: Populate Database Tables & Menu Data

# Feed the complete SQL schema and dishes catalog directly into the MySQL pod
Get-Content database\schema.sql | kubectl exec -i mysql-0 -- mysql -u restaurant_user -pAdmin@123 restaurant_db

Step 4: Build Microservice Images & Load to Minikube

# 1. Build Backend API Docker image
docker build -t restaurant-backend:v1.0 ./backend

# 2. Build Kafka Payment Consumer Docker image
docker build -t restaurant-payment-consumer:v1.0 ./consumer

# 3. Build Nginx Frontend Docker image
docker build -t restaurant-frontend:v1.0 ./frontend

# 4. Transfer images directly into Minikube internal cache
minikube image load restaurant-backend:v1.0
minikube image load restaurant-payment-consumer:v1.0
minikube image load restaurant-frontend:v1.0

Step 5: Launch Microservices Deployments

# Deploy Backend API layer
kubectl apply -f k8s/backend/backend-deployment.yml
kubectl apply -f k8s/backend/backend-service.yml

# Deploy Kafka Consumer worker
kubectl apply -f k8s/consumer/payment-consumer-deployment.yml

# Deploy Frontend reverse proxy and UI pods
kubectl apply -f k8s/frontend/frontend-configmap.yml
kubectl apply -f k8s/frontend/frontend-deployment.yml
kubectl apply -f k8s/frontend/frontend-service-nodeport.yml

# Monitor rollout progression
kubectl rollout status deployment/backend-deployment
kubectl rollout status deployment/payment-consumer-deployment
kubectl rollout status deployment/frontend-deployment

Step 6: Expose Frontend Service & Stream Logs

# Terminal 1: Stream real-time consumer terminal logs
kubectl logs -f -l app=payment-consumer

# Terminal 2: Expose frontend to web browser
minikube service frontend-service-nodeport
